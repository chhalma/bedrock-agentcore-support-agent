## Reflection

**Design decision: Exact arithmetic in a sandbox, not in the model.** For loyalty discounts, I deliberately avoided having the LLM calculate prices directly. Instead, I passed generated Python code to the AgentCore Code Interpreter, because LLMs generate predictions rather than perform guaranteed-exact arithmetic. In a customer-facing billing workflow, even a confidently stated but incorrect total is unacceptable. The tool injects the customer's points balance, tier and order total into a self-contained script that applies the business rules: redemption in 500-point blocks, a 50% cap on points redemption, and the tier discount applied after points. It returns a structured JSON breakdown. If the sandbox is unavailable, a fallback applies only the tier discount and explicitly identifies the result as partial. I applied the same graceful-degradation principle to the memory hook: retrieval and saving are wrapped so that memory failures do not block support. I also strip the injected *Customer Context* before saving each turn, preventing retrieved memories from being fed back into storage and duplicated over time.

**Challenge: Deploying a Linux agent from Windows.** The agent worked locally, but deployment failed four times for different reasons. The toolkit required a `zip` binary unavailable in my Windows environment. Dependency resolution then selected Windows-specific packages, including `pywin32`, which has no Linux build. The package also included the OpenTelemetry launcher as a Windows `.exe`. Finally, the browser tool failed with `Permission denied` because the ZIP archive did not preserve the Unix executable permissions required by Playwright's Node.js driver. I diagnosed these issues by inspecting the toolkit's source code and CloudWatch logs. I generated a `requirements.txt` resolved for the `aarch64-manylinux` target, disabled the Windows-built tracing launcher, and corrected the Linux executable permissions in the cached package. Separately, the agent initially refused to browse. Clarifying the system prompt to explicitly state that browsing was available and permitted resolved the issue.

**Production extensions.** I would replace the Gateway's `NONE` authorizer with JWT-based authentication, such as Amazon Cognito, and derive `customer_id` from the authenticated identity rather than trusting a client-supplied payload. Refunds would integrate with the authoritative order database, use idempotency keys to prevent duplicate transactions, and require human approval above a defined threshold. I would also build deployment packages in Linux CI, re-enable tracing, add Amazon Bedrock Guardrails for PII and prompt-injection risks, and run an automated evaluation suite covering the six defined scenarios before every deployment.
